vivado_synthesis

load("@rules_vivado//vivado:synthesis.bzl", "vivado_synthesis")

vivado_synthesis(name, jobs, post_hooks, pre_hooks, project, project_mode, reports, synth_args,
                 synth_invocation, synth_strategy, synthesis_tcl_template)

Run synthesis on a vivado_project. Sources the project's emitted TCL script inside a single Vivado action, generates IP / BD targets (global synthesis — no OOC runs), runs the top synth (launch_runs or synth_design), and writes a .dcp checkpoint + impl-XDC bundle for downstream implementation phases.

project_modeHow Vivado stores project state. project creates a named on-disk project so managed-run infrastructure (launch_runs, synth_1) is available. in_memory calls create_project -in_memory; managed runs are unavailable, so synth_invocation = launch_runs requires project. The two modes can produce different netlist hierarchies for block-design-instantiated IPs, affecting downstream physical constraints that target IP-internal cells/nets.Stringoptional"project"
reportsReport types to run after synth_design, before checkpoint write. Each entry must be a key in REPORT_TYPES (vivado/private/common.bzl). Reports live at <target>.reports/<filename> and are wrapped in catch so a single failure writes an empty file rather than aborting. Pass reports = [] to disable.List of stringsoptional["timing_summary", "utilization"]
synth_argsExtra flags for synth_design in the synth_design invocation path. Cannot contain -top (the rule emits that from the project's module_top). Not consulted on the launch_runs path; there, set STEPS.SYNTH_DESIGN.ARGS.* run properties from a pre_hooks script.List of stringsoptional[]
synth_invocationHow synth_design is invoked. launch_runs wraps it in a managed synth_1 design-run (fresh Vivado process re-loads project state from disk). synth_design invokes it in the same process. Multi-config XCI consumer instantiations require synth_design: in launch_runs the re-loading process binds consumer wrappers to the IP's project-managed synth wrapper (which doesn't propagate consumer-side generics), so wrappers passing distinct generic combinations surface as __parameterized<N> black boxes.Stringoptional"launch_runs"
synth_strategyThe synthesis strategy to use.Stringoptional"Vivado Synthesis Defaults"
synthesis_tcl_templateThe synthesis tcl template.Labeloptional"@rules_vivado//vivado/private:synthesis.tcl.template"
