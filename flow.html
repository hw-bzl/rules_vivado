Rule flow

How the rules connect. Every vivado_* rule resolves the Xilinx install through the registered vivado_toolchain; that edge is left out of the diagrams below because it reaches every node.

Each box is a rule. Each arrow is a Bazel dependency, labelled with the attribute on the consuming rule and the provider that crosses it. Boxes outside the dashed groups come from other rulesets.

vivado_compile_simlib stands alone: it pre-compiles the Xilinx simulation libraries for a third-party simulator and hands the result to whatever consumes a vivado_export_simulation bundle, outside this ruleset.

Project to bitstream

The implementation chain is one rule per Vivado command, and each rule accepts the provider of the phase before it. The two optimization phases are optional: vivado_placement takes a VivadoSynthCheckpointInfo from either vivado_synthesis or vivado_synthesis_optimize, and vivado_routing takes a VivadoPlacementCheckpointInfo from either vivado_placement or vivado_place_optimize.

    SYN["vivado_synthesis<br/><i>synth_design, .dcp + impl-XDC bundle</i>"]
    SOPT["vivado_synthesis_optimize<br/><i>opt_design</i>"]
    PLC["vivado_placement<br/><i>place_design</i>"]
    POPT["vivado_place_optimize<br/><i>phys_opt_design</i>"]
    RTE["vivado_routing<br/><i>route_design</i>"]
    BIT["vivado_bitstream<br/><i>write_bitstream</i>"]
    PDI["vivado_device_image<br/><i>write_device_image (Versal)</i>"]
    XSA["vivado_hw_platform<br/><i>write_hw_platform</i>"]
    LTX["vivado_debug_probes<br/><i>write_debug_probes</i>"]

    SYN -- VivadoSynthCheckpointInfo --> SOPT
    SYN -. "optional phase skipped" .-> PLC
    SOPT -- VivadoSynthCheckpointInfo --> PLC
    PLC -- VivadoPlacementCheckpointInfo --> POPT

    PLC -. "any checkpoint provider" .-> LTX

Two providers ride along the whole chain rather than crossing a single edge:

  • VivadoLogInfo accumulates every upstream phase's .log and .jou, so building :my_bitstream with --output_groups=log yields the logs of synthesis through bitstream.
  • VivadoReportsInfo maps each phase's reports attr to its declared report files.

Every phase rule also carries pre_hooks and post_hooks: .tcl, .xdc, .sdc files or tcl_binary targets sourced inside the Vivado session before and after the phase's main command.

IP composition

IP enters a project in two shapes. VivadoIPBlockInfo describes a repo plus, optionally, a configured .xci or a VLNV to create_ip; VivadoBlockDesignInfo describes a .bd and the IP repos it needs.

flowchart LR
    SV["SystemVerilog<br/>interface .sv"]
    IFD[vivado_interface_definition]
    IFIP[vivado_interface_ip]
    VL["verilog_library<br/>vhdl_library"]
    IPC[vivado_ip_core]
    XCI[vivado_xci]
    PIP[vivado_packaged_ip]
    BD[vivado_block_design]
    PRJ[vivado_project]

    SV -- src --> IFD
    IFD -- "interface<br/>VivadoInterfaceInfo" --> IFIP
    VL -- module --> IPC
    VL -- hdl_libraries --> PIP
    IFIP -- "ip_blocks<br/>VivadoIPBlockInfo" --> IPC
    XCI -- "ip_blocks" --> IPC
    IFIP -- ip_blocks --> BD
    IPC -- ip_blocks --> BD
    XCI -- ip_blocks --> BD
    PIP -- ip_blocks --> BD
    IPC -- ip_blocks --> PRJ
    XCI -- ip_blocks --> PRJ
    PIP -- ip_blocks --> PRJ
    BD -- "block_designs<br/>VivadoBlockDesignInfo" --> PRJ
    XCI -. "deps<br/>VerilogInfo / VhdlInfo" .-> VL
  • vivado_xci configures a Xilinx-catalog IP from a tcl_binary script. Besides VivadoIPBlockInfo it exposes VerilogInfo and VhdlInfo, so it can also sit in a verilog_library's deps (dashed edge).
  • vivado_ip_core packages your own HDL as a reusable IP core.
  • vivado_interface_definition turns a SystemVerilog interface into IP-XACT bus and abstraction definitions; vivado_interface_ip registers them as a catalog entry so block designs can connect to it.
  • vivado_packaged_ip stages an already-packaged IP repo.
  • vivado_block_design builds a .bd from a tcl_binary script and forwards the IP repos its cells reference.

Any of these can contribute project_hooks: Tcl sourced inside every downstream vivado_project that folds the target in, right after create_project.

Simulation and export

flowchart LR
    PRJ[vivado_project]
    XSIM["vivado_xsim_test<br/><i>bazel test</i>"]
    EXS["vivado_export_simulation<br/><i>export_simulation bundle</i>"]
    PEX["vivado_project_export<br/><i>user script, declared outs</i>"]
    SIMLIB["vivado_compile_simlib<br/><i>compile_simlib</i>"]
    EXT["third-party simulator<br/>(outside rules_vivado)"]

    PRJ -- "project<br/>VivadoProjectInfo" --> XSIM
    PRJ -- "project" --> EXS
    PRJ -- "project" --> PEX
    EXS -- VivadoExportSimulationInfo --> EXT
    SIMLIB -- VivadoCompiledSimlibInfo --> EXT
  • vivado_xsim_test exports an xsim bundle at build time and runs it as a Bazel test, scanning the log for error and completion patterns.
  • vivado_export_simulation produces the same kind of bundle for any simulator Vivado's export_simulation supports and stops there.
  • vivado_project_export opens the project, sources a user tcl_binary, and captures whatever files or directories that script writes.
  • vivado_compile_simlib pre-compiles unisim, secureip and friends for a third-party simulator.
